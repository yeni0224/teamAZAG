# UI 가이드

이 문서는 시각 디자인 기준을 정의한다. 제품 사용자 여정과 화면 흐름은 `docs/PRODUCT_UX.md`를 따르고, 하네스 CLI/로그/복구 UX는 `docs/HARNESS_UX.md`를 따른다.

## 디자인 원칙
1. 도구처럼 보여야 한다. 마케팅 페이지가 아니라 매일 쓰는 작업 화면을 우선한다.
2. 정보 밀도와 가독성을 우선한다. 큰 장식보다 상태, 로그, diff, 검증 결과, 출처가 잘 보여야 한다.
3. AI 냄새 나는 장식을 피한다. 기능과 상태를 드러내는 UI를 만든다.
4. 운영 판단에 필요한 근거를 숨기지 않는다. 요약 옆에는 source id, 원문 링크, confidence, 추론 여부를 보여준다.
5. 사용자가 다음 행동을 바로 선택할 수 있어야 한다.

## 금지할 AI 슬롭 패턴
| 금지 사항 | 이유 |
|-----------|------|
| 배경 gradient orb | 흔한 AI 랜딩 페이지 장식이라 정보성이 없다 |
| 보라/인디고 일변도 팔레트 | "AI 서비스" 클리셰처럼 보인다 |
| gradient text | 제목을 읽기 어렵게 만들고 템플릿 느낌을 준다 |
| glass morphism blur | 도구 UI에서 대비와 밀도를 해친다 |
| 과한 glow/shadow | 로그와 상태 화면에서 시각 노이즈가 된다 |
| 모든 카드에 큰 radius | 반복 UI가 장난감처럼 보일 수 있다 |
| "Powered by AI" 배지 | 사용자에게 동작이나 상태 정보를 주지 않는다 |

## 운영 인텔리전스 화면 기준
첫 화면에서 다음 질문에 답해야 한다.

- 지금 운영 상태는 정상인가, 위험한가?
- 가장 중요한 리스크는 무엇인가?
- 무엇이 막혔고 누가 풀어야 하는가?
- 오늘 처리해야 할 TODO는 무엇인가?
- 최근 결정 사항은 무엇인가?
- 새 담당자가 이어받으려면 무엇을 읽어야 하는가?

## 하네스 대시보드를 만들 경우
하네스 UI는 다음 정보를 첫 화면에서 보여준다.

- phase 목록과 상태
- 현재 running/pending step
- 최근 실패 원인
- Acceptance Criteria 결과
- 마지막 trace/result 파일 링크
- retry 횟수
- git branch와 commit 상태
- 다음에 실행할 명령

## 레이아웃 기준
- 좌측 정렬을 기본으로 한다.
- 로그와 JSON은 모노스페이스로 보여준다.
- 카드 중첩을 피한다.
- 상태 색상은 적게 쓴다.
- 화면의 주요 액션은 명확한 동사로 제한한다.
- 운영 인텔리전스 화면은 `Overview`, `Risks`, `Blocked`, `TODO`, `Knowledge`, `Handover`, `Review`, `Evidence` 같은 명확한 섹션을 가진다.

## 색상 기준
| 용도 | 예시 |
|------|------|
| 배경 | `#0f1115` 또는 시스템 기본 배경 |
| 표면 | `#171a21` |
| 경계 | `#2a2f3a` |
| 본문 | `#e5e7eb` |
| 보조 | `#9ca3af` |
| 성공 | `#22c55e` |
| 실패/긴급 리스크 | `#ef4444` |
| blocked/주의 | `#f59e0b` |
| 정보/출처 | `#38bdf8` |

## 컴포넌트 기준
- 버튼은 명확한 동사로 짧게 쓴다.
- 아이콘은 의미가 분명할 때만 쓴다.
- 로그 영역은 줄바꿈, 복사, 검색이 가능해야 한다.
- 테이블은 phase/step/status/updated_at/summary 또는 item/owner/due/source/status를 빠르게 훑을 수 있어야 한다.
- 리스크와 Blocked 이슈는 severity, owner, required decision, source를 함께 보여준다.
- 인수인계 화면은 "현재 맥락", "남은 작업", "주의사항", "핵심 링크", "첫 행동"을 분리한다.
- Review queue는 confirm, edit, dismiss, merge, open source를 제공한다.

## 빈 상태와 오류 상태
- 데이터가 없으면 다음 입력 방법을 안내한다.
- source가 없으면 주요 insight로 승격하지 않는다.
- 낮은 confidence는 원문 확인 액션을 함께 보여준다.
- blocked 상태는 필요한 결정과 담당자를 보여준다.
- stale 항목은 현재 유효성 확인 액션을 보여준다.

## 애니메이션
상태 전환이나 로딩 표시처럼 기능적 의미가 있을 때만 짧게 사용한다. 장식용 애니메이션은 쓰지 않는다.
