# PRODUCT: AI 기반 운영 인텔리전스 시스템

## 한 줄 정의
조직 내 흩어진 운영 기록(메일, 채팅, 회의록, 업무 문서 등)을 AI가 분석해 운영 상태, 주요 리스크, TODO, Blocked 이슈, 조직 지식, 인수인계 정보를 자동으로 구조화하는 운영 인텔리전스 시스템이다.

## 문제 정의
조직의 실제 운영 맥락은 여러 도구에 흩어져 있다.

- 메일에는 외부 커뮤니케이션과 승인 맥락이 있다.
- 채팅에는 빠른 의사결정, 장애 상황, 임시 TODO가 있다.
- 회의록에는 결정 사항과 책임자가 있다.
- 업무 문서에는 정책, 절차, 배경 지식, 인수인계 내용이 있다.

이 정보가 흩어져 있으면 리더와 실무자는 현재 상태를 늦게 파악하고, 리스크와 막힌 이슈를 놓치며, 담당자 변경 시 지식 손실을 겪는다.

## 목표
비정형 운영 데이터를 분석해 조직 운영에 필요한 구조화 정보를 자동 생성한다.

- 현재 운영 상태를 한눈에 보여준다.
- 주요 리스크와 Blocked 이슈를 조기에 드러낸다.
- TODO와 담당자, 기한, 출처를 추출한다.
- 반복되는 조직 지식과 의사결정 맥락을 축적한다.
- 담당자 변경이나 휴가, 퇴사, 프로젝트 전환 시 인수인계를 빠르게 만든다.

## 주요 사용자
- 조직장/팀장: 운영 상태와 리스크를 빠르게 파악한다.
- PM/PO/운영 담당자: TODO, 의존성, 막힌 이슈를 추적한다.
- 신규 담당자: 기존 맥락과 인수인계 정보를 이해한다.
- 실무자: AI 추출 결과를 검토하고 수정한다.
- 관리자/보안 담당자: 데이터 접근, 보존, 삭제 가능성을 확인한다.

자세한 사용자 여정은 `docs/PRODUCT_UX.md`를 따른다.

## 핵심 산출물
| 산출물 | 설명 |
|------|------|
| 운영 상태 | 최근 진행 상황, 건강도, 변화, 이상 징후 |
| 주요 리스크 | 일정 지연, 품질 저하, 의존성, 의사결정 지연, 담당자 공백 |
| TODO | 실행 항목, 담당자, 기한, 우선순위, 근거 출처 |
| Blocked 이슈 | 막힌 이유, 필요한 결정, 외부 의존성, 다음 액션 |
| 조직 지식 | 반복되는 규칙, 노하우, 결정 배경, 정책, FAQ |
| 인수인계 정보 | 현재 맥락, 남은 일, 주의사항, 핵심 링크, 담당자 맵 |

각 산출물의 필드 구조는 `docs/DATA_MODEL.md`를 따른다.

## UX 원칙
- 사용자는 AI 결과를 검토할 수 있어야 한다.
- 모든 핵심 항목은 source evidence를 가져야 한다.
- confidence가 낮거나 추론 기반인 항목은 명확히 표시한다.
- 인수인계 정보는 새 담당자의 첫 행동까지 연결되어야 한다.
- 리포트는 단순 요약이 아니라 다음 행동을 정하게 해야 한다.

## MVP 범위
- 샘플 운영 기록을 입력으로 받는 파일 기반 ingestion
- 회의록/채팅/문서 텍스트를 공통 record 형식으로 정규화
- TODO, 리스크, Blocked 이슈, 결정 사항, 인수인계 메모 추출
- 추출 결과에 원문 출처와 신뢰도 표시
- review_status 기반의 검토 흐름 모델링
- 대시보드 또는 리포트 형태의 요약 출력
- 테스트 가능한 fixture와 deterministic parser/formatter

## MVP 제외 사항
- 실제 Gmail/Slack/Notion/Jira 연동
- 실시간 스트리밍 수집
- 권한/조직도 전체 동기화
- 프로덕션용 벡터 DB 또는 외부 검색 인프라
- 자동 액션 실행(메일 발송, 티켓 생성 등)
- 민감정보가 포함된 실제 고객 데이터 처리

## 데이터 원칙
- 모든 추출 결과는 원문 출처를 가져야 한다.
- AI가 추론한 내용과 원문에 명시된 내용을 구분한다.
- 개인 정보와 비밀값은 마스킹 또는 fixture로 대체한다.
- 사용자가 삭제해야 하는 데이터는 추적 가능해야 한다.
- 운영 판단에 쓰이는 요약은 근거 링크나 record id를 제공한다.
- 보안과 개인정보 기준은 `docs/SECURITY_PRIVACY.md`를 따른다.

## 평가 원칙
평가 기준은 `docs/EVALUATION.md`를 따른다.

- TODO, Risk, Blocked, Decision 추출은 fixture 기반으로 검증한다.
- source attribution이 없는 주요 insight는 실패로 본다.
- hallucination, stale carryover, wrong owner를 명시 실패 유형으로 본다.

## 성공 기준
- 샘플 입력에서 TODO, 리스크, Blocked 이슈, 결정 사항을 안정적으로 추출한다.
- 리포트가 “무슨 일이 진행 중이고, 무엇이 막혔고, 누가 무엇을 해야 하는지”를 보여준다.
- 새 담당자가 리포트만 읽어도 핵심 맥락과 다음 행동을 이해할 수 있다.
- 사용자가 AI 결과를 confirm, edit, dismiss, merge 할 수 있는 구조가 있다.
- 테스트가 외부 서비스 없이 재현 가능하게 통과한다.
